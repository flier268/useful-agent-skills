# /fix

修正目前發現的問題，避免使用補釘的方式修正，使用正確地方式修正問題，如果需要重構才能達成就重構。

## 問題來源

一併收集，不要只修表面一個症狀：

- 這次對話裡已指出的缺陷、錯誤假設、錯誤設計
- 工作區 git 差異與未完成變更暴露的問題
- 失敗測試、linter、型別錯誤
- 審查意見或明顯的回歸

範圍停在「目前已發現」的問題與其正確根因。不要順便做無關清理。

## 禁止補釘

下列都算補釘，不要用：

- 只改呼叫端／UI／測試來遷就錯誤的核心行為
- 特例、flag、硬編碼、swallow error、重複邏輯、多餘轉換層
- 為了讓測試綠而放寬斷言或複製錯誤行為
- 在錯誤的抽象層加 if，卻不修正擁有該不變條件的模組
- 留下「之後再清」的暫時分支

症狀消失但根因還在，就不算完成。

## 正確修法

1. 寫下每個問題的根因：錯在哪個不變條件、哪個模組該負責。
2. 在擁有該責任的地方改行為；呼叫端只改成配合正確契約。
3. 現有結構無法乾淨表達正確行為時就重構：搬責任、拆模組、改資料流、刪重複。重構服務於這個修正，不是另開重構專案。
4. 刪掉因錯誤設計而存在的 workaround。
5. 用能鎖住根因的測試覆蓋；必要時改測試以符合正確契約，不要改產品去迎合錯的測試。
6. 跑與變更相關的測試。相關測試失敗就繼續修，不要用跳過或弱化斷言過關。

## 完成時

簡短說明：修了什麼、根因、為何不是補釘、若有重構改了哪層契約。
